**Test date:** 2026-09-27

**App:** LSS Annual Planner_V1 (Power Apps Canvas app)

**Test account/environment:** `abbasi (default)`; shared planner and Outlook test account
**Evidence basis:** Power Apps preview/runtime checks, current Canvas YAML synced from Power Apps, Canvas compile validation, App Checker, and accessibility checker. At the end of testing, Studio displayed **Saved (Unpublished)**; the visible “Publish successful” toast was timestamped 8:42 PM. **Data safety:** Created two clearly labeled test records in the existing demo/test SharePoint lists. The Rule Book test rule is soft-deleted in the test list. Did not reset the calendar, alter pre-existing rules/events, or perform outbound Outlook writes/invitations.

## Executive result

Core navigation, loading of the saved 2027 plan, layer filtering, meeting selection/details, recurrence option visibility, read-only Outlook fetch, and labeled test-record create/save/reload flows were exercised. Rule Book create/delete/undo worked in-session. The current app YAML compiles and the accessibility checker reports no errors. **A critical manual-meeting deletion failure was found:** the one-off returned after a cold reload; its exact test row was then removed directly from the demo list so it does not remain in the planner.

This is **not a full release sign-off**. The highest-risk destructive and outbound-write paths were not run against the shared data. One confirmed acceptance failure is that **Reset calendar removes all meetings in the selected year, including manual one-off meetings**, contrary to the requested safe behavior (“Delete meetings from rules” should leave hand-entered meetings intact). The current app is also still wired to the `LSS Test … 20260921` SharePoint lists, so it is not ready for deployment against LSS production data. App Checker reports 27 medium performance warnings. Studio currently says **Saved (Unpublished)**, so confirm the intended final state is published before a demo.

## Status key

- **PASS — runtime:** exercised in the published app preview and the expected result was visible.
- **PASS — static:** the current saved formula/source implements the criterion, but the corresponding mutating flow was not executed.
- **FAIL:** observed behavior conflicts with the acceptance criterion or explicit product decision.
- **BLOCKED — safety:** needs a genuinely isolated test copy/list or explicit deployment authorization; not safe to test on the shared planner.
- **NOT RUN:** not exercised in this pass; should be tested before release.

## Findings to resolve before demo/release

1. **Critical: manual meeting deletion does not persist.** A manual one-off disappeared after the app’s Delete action, then returned after a cold reload. Fix the app-level persistence/tombstone path before demo sign-off; retest delete and reload in an isolated app/list. The acceptance-test row was removed directly from the demo list after the failure was captured.
2. **Reset is unsafe for one-offs and does not match the requested action.** Current UI says “Reset calendar” and the formula removes every event row for the year, including manual events. Change the operation to “Delete meetings from rules” and explicitly retain one-off/manual events before this can be accepted. Test the actual delete/undo only in an isolated app **and** isolated SharePoint list.
3. **Confirm published state before demo.** Studio currently says “Saved (Unpublished)” although a prior publish-success toast is present. Publish only after reviewing the intended final state, then open the published app—not Studio preview—for the demo smoke test.
4. **Production deployment is not ready.** The app currently reads/writes the test SharePoint lists. Prepare the production LSS lists/permissions and remap the app in a deployment copy; do not point the demo/test app at production data.
5. **ICS and PDF year downloads are missing.** The user asked for a 12-month backup/download; add this to the acceptance scope if it remains a demo requirement.
6. **No demonstrated named board checkpoint/restore.** Automatic persistence exists, but a clear “saved at” indicator and version/restore path are not established. Clarify whether SharePoint version history is sufficient for the user workflow and validate it with a cold reload.
6. **27 App Checker performance warnings.** Prioritize year-screen control count (301) and datasource completeness/delegation warnings before handing the app to many users or large datasets.
7. **Outbound Outlook end-to-end cases remain unproven in this test pass.** Earlier manual demo activity reported successful sync, but this pass did not create/update events or send attendee invitations. Verify dedupe, attendee invitations, retry/reconciliation, and per-user destination using unique disposable test data before calling sync fully accepted.
8. **Holiday/closure content is test fixture data.** Replace and validate it against LSS’s actual closure calendar and policy before use beyond the demo.
